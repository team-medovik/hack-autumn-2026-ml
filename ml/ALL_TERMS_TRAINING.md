# Модель для часовых, суточных и месячных VPS

25 октября 2026. Новая модель `event-driven-all-terms-v1-234422ba1357` обучена на
36 прежних признаках с CatBoost Logloss. Бизнес-правила генератора, определения
платежей, замен и нефинансовых ограничений не менялись.

## Данные и разделение

- 10 независимых миров по 40 клиентов, горизонт каждого — 180 дней.
- 400 синтетических клиентов, 133 889 событий, 18 571 наблюдение услуг.
- 11 190 строк train, 4 047 validation, 3 080 test. Ещё 214 наблюдений имеют
  незавершённый исход, 40 исключены из-за нефинансовых ограничений.
- Миры с seeds 2026102601–2606 — train, 2607–2608 — validation, 2609–2610 — test.
  Распределение зафиксировано до генерации и обучения. Клиент обозначается парой
  `(worldId, accountId)`; один клиент и его услуги не переходят между частями.
- Даты первой покупки распределены по первым 30 дням. Архетипы имеют прежние равные
  шансы; бюджет и потребность формируются независимо. Тариф day по-прежнему
  синтетический, цена — 24 часовых платежа.

Наблюдение выбирается **до присвоения метки**: ежедневный срез в 15:00 UTC, а для
hour/day дополнительно первый цикл через половину оплаченного периода. Иначе
ежедневная сетка пропускала бы услуги, потерянные уже на первом часовом продлении.
Это не выбор только удачных или рискованных примеров. При этом такой тест не
проверяет каждый часовой цикл: его выводы относятся к указанной сетке наблюдений.

Метка прежняя: `1`, если к сроку оплаты + 5 суток нет успешного продления или
подтверждённой оплаченной замены; `0` при продлении/замене. Пересечение окна исхода
с нефинансовым ограничением исключает наблюдение из обучения. Прогноз делается
строго до срока оплаты, в пределах 7 дней; будущее, скрытые потребности, архетип,
бюджет, seed, ID и доказательства метки в признаки не входят.

## Обучение и решение о поддержке периодов

Параметры зафиксированы заранее: максимум 300 деревьев, глубина 4, learning rate
0,05, Logloss, seed 20261024, 2 потока. Validation выбирает число деревьев;
сохранено **101 дерево**. Перебора по test и перекалибровки нет.

Суммарный вес наблюдений одного цикла — 1. В `fit` и validation eval_set суммарный
вес каждого периода одинаков: часовые/суточные циклы не вытесняют месячные просто
своим количеством. Балансировки положительного/отрицательного класса нет.

До расчёта test зафиксирован критерий включения периода: минимум 10 положительных
и 10 отрицательных validation-циклов, Logloss и Brier ниже константы соответствующего
периода. Константа — доля потерь **train**: hour 3,3419%, day 4,6404%, month 17,0103%.
Все три периода прошли этот критерий. Файл `validation-decision.json` сохраняется
до вычисления test-прогнозов. Этот критерий не доказывает качество на реальных клиентах.

## Результаты отдельно по периоду

Каждый столбец оценивает те же строки. Для старой месячной модели ответы на hour/day
даны только как диагностический запуск вне её прежней области обучения.

| Validation | Циклы / потери | Logloss новая | Старая 36 | Константа | Brier новая / константа |
|---|---:|---:|---:|---:|---:|
| Час | 236 / 16 | 0,1658 | 0,2553 | 0,2621 | 0,0511 / 0,0644 |
| Сутки | 2 612 / 134 | 0,1583 | 0,2864 | 0,2026 | 0,0401 / 0,0487 |
| Месяц | 168 / 36 | 0,4399 | 0,4446 | 0,5261 | 0,1403 / 0,1703 |

| Test | Циклы / потери | Logloss новая | Старая 36 | Константа | AUC новая | Brier новая / старая / константа |
|---|---:|---:|---:|---:|---:|---:|
| Час | 246 / 12 | 0,1525 | 0,2451 | 0,1981 | 0,8793 | 0,0407 / 0,0609 / 0,0466 |
| Сутки | 1 750 / 122 | 0,1877 | 0,3180 | 0,2583 | 0,8610 | 0,0516 / 0,0882 / 0,0654 |
| Месяц | 158 / 32 | 0,4531 | 0,4409 | 0,5074 | 0,7317 | 0,1485 / 0,1397 / 0,1626 |

Новая модель лучше соответствующей константы по Logloss/Brier во всех периодах.
**На месячном test старая модель лучше новой по Logloss и Brier.** AUC новой чуть
выше (0,7317 против 0,7245), что не отменяет ухудшение ошибок вероятности.
После обнаружения этого результата параметры и выборка не менялись. Нельзя говорить,
что качество улучшилось для каждого периода, или выбирать другую модель по этому test
и продолжать называть его независимой финальной проверкой.

12 часовых потерь в test — мало для уверенного вывода. Все миры следуют одним
синтетическим гипотезам; новые seeds/клиенты не превращают проверку в реальные данные.

## Примеры и файлы

В `ml/runs/all-terms-v1/integration-examples/index.json` — 12 иллюстраций: высокая
оценка при потере, низкая при продлении и две противоположные ошибки для каждого
периода. Они выбраны после оценки как контрасты, а не как оценка распространённости.
Рядом для каждого случая есть полный наблюдаемый HTTP request и RiskSnapshot на
момент прогноза; будущая метка находится только в отдельном index.

- Истории: `ml/runs/all-terms-v1/histories/world-*.json`.
- Строки: `ml/runs/all-terms-v1/rows.jsonl`.
- Все ответы новой/старой/константы: `ml/runs/all-terms-v1/predictions.jsonl`.
- Артефакт и manifest: `model.cbm`, `model-manifest.json` в этом же каталоге.
- Сводный отчёт в Git: [reports/all-terms-v1.json](reports/all-terms-v1.json).
- Большие файлы `ml/runs/` локальные и исключены из Git; артефакт для сервиса
  отдельно включается в `inference_service/artifacts/`.

Повторить эксперимент, не перезаписывая результаты:

```sh
ml/.venv/bin/python ml/train_all_terms.py --output /absolute/path/new-all-terms-run
```

## Проверки

7 тестов: отдельные seeds миров; все периоды и неизменная метка; покрытие первого
часового цикла; совпадение признаков полного журнала с его префиксом до predictionAt;
отклонение будущего доказательства/пересечения клиента между split; веса периодов;
точное воспроизведение сохранённых вероятностей артефактом для всех трёх периодов.
Полный прогон также проверил 36 признаков, уникальность строк и отсутствие переходов
циклов/клиентов между частями. Старая модель не изменялась.
