# ML inference: независимый FastAPI

Этот процесс загружает готовый CatBoost и вычисляет вероятность потери VPS.
Он не обучает модель, не запускает генератор и не меняет баланс. Поправку к баллу
алгоритма (30%, максимум ±20) применяет Kotlin; публичный контракт Kotlin не меняется.

## Запуск

В репозитории сохранены малый бинарный артефакт и manifest в `artifacts/`.
Manifest фиксирует SHA-256, порядок 36 признаков, версии схемы/метки и периоды.
Модель `event-driven-all-terms-v1-234422ba1357` поддерживает `hour`, `day`, `month`;
суточный тариф остаётся синтетическим. Старый месячный артефакт можно подключить
отдельной конфигурацией: его manifest должен указывать только `month`.

```sh
# ML_SERVICE_TOKEN должен содержать минимум 16 байт.
docker compose -f compose.ml.yaml up -d --build
```

FastAPI доступен локально на `127.0.0.1:8012`, внутри сети — `ml-service:8000`.
Для Kotlin нужно подключить контейнер к той же внутренней Docker-сети. Локально:

```sh
python -m pip install -r inference_service/requirements.txt
python -m uvicorn inference_service.api:create_app --factory --host 127.0.0.1 --port 8012
```

| Переменная | Назначение |
|---|---|
| `ML_SERVICE_TOKEN` | Bearer secret; обязательный, не пользовательский JWT |
| `ML_MODEL_PATH` | Путь к model.cbm; по умолчанию встроенный `artifacts/model.cbm` |
| `ML_MODEL_MANIFEST_PATH` | Manifest артефакта; по умолчанию `artifacts/manifest.json` |
| `ML_MAX_BODY_BYTES` | Лимит тела до разбора/replay; по умолчанию 32 MiB, максимум 64 MiB |

Модель загружается один раз. При отсутствующем/несовместимом артефакте процесс жив,
но readiness и inference возвращают 503; замену артефакта активирует рестарт.
Секреты и сырые ошибки артефакта не выдаются наружу.

## Существующий внутренний контракт

- `GET /health/live` — процесс жив.
- `GET /health/ready` — модель успешно загружена и проверена.
- `GET /internal/v1/model` — версия, SHA, порядок признаков и поддержанные периоды.
- `POST /internal/v1/renewal-risk/predict` — один результат для каждой запрошенной VPS.

Форма запросов/ответов в [OpenAPI](../contracts/openapi.yaml) сохранена. Enum периодов
ModelInfo расширен до hour/day/month. Все маршруты, кроме health, требуют Bearer token.

Для живого источника Kotlin передаёт `input.kind=history`, полный опубликованный
префикс журнала от регистраций аккаунтов, runId, asOf, predictionAt и snapshotRevision.
`serviceIds` ограничивает результаты, а не портфель/историю. Email передавать не нужно.
Обычные JSON-снимки поддержаны: ответ `insufficient_data/SNAPSHOT_HAS_NO_HISTORY`,
а не выдуманная история. Вход `dataset` пока возвращает явный 503: MinIO registry
ещё не реализован, произвольные URL/пути сервис не загружает.

## Признаки, отказы и отсутствие утечек

Используется тот же `EventHistory.features_at`, что и при обучении. В модель не
передаются метки, будущие решения клиента, seed или архетип. Учитываются только
события с обеими датами occurredAt/recordedAt не позже predictionAt. Полный будущий
суффикс журнала может присутствовать в запросе, но не входит в признаки.

Прогноз возможен до срока оплаты, в окне `0 < dueAt−predictionAt <= 7 суток`.
Метка остаётся общей: нет продления/подтверждённой оплаченной замены к dueAt+5 суток.
Для коротких периодов это критерий потери услуги, не вероятность пропуска одного
часового платежа. `prolong_wait`, просрочка, удаление/замена и действующее
нефинансовое ограничение дают `not_applicable` с причиной, probability=null.

Дубли ID, неверные типы, даты и неизвестные поля отклоняются 422. История проверяется
на регистрации, владельцев, последовательные балансы и оплаты. При противоречии
событий аккаунта прогнозы его услуг не выдаются; остальные согласованные аккаунты
могут оцениваться. Отклонённая покупка несуществующей VPS — допустимое событие.
Произвольно вырезанную услугу без оставшихся ссылок невозможно обнаружить локально:
полноту журнала обязан обеспечивать отправитель по сохранённому курсору источника.

Нельзя подставлять 0 вместо отсутствующей вероятности. Ошибка модели/сервиса должна
возвращать API к исходному алгоритму. В ответе сохраняются requestId, snapshotRevision
и predictionAt; Kotlin обязан отвергать несовпадение и неожиданную версию модели.

## Проверка

12 HTTP/inference проверок с настоящим CatBoost прошли: точное совпадение старых
сохранённых прогнозов и новых hour/day/month прогнозов, отсутствие влияния будущих
событий и поздней записи, полный контекст портфеля, отказы/ошибки/лимиты, hash/feature
схема модели. Дополнительно 9 OpenAPI tests. Новый Docker-образ собран отдельно от
генератора; ML-зависимости в образ генератора не добавляются.

Данные, метрики и ограничения нового обучения описаны в отчёте `ml/ALL_TERMS_TRAINING.md`
Это синтетические проверки, не доказательство
качества на настоящих клиентах. Перед PR новые тестовые исходники убираются из
публикации согласно инструкции пользователя; локальные результаты сохраняются в runtime.
